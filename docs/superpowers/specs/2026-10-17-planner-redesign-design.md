# «Мой план» — редизайн мини-приложения Telegram (часть 1)

Дата: 2026-10-17 · Статус: на согласовании

## 1. Цель

Личное мини-приложение Telegram для учёта денег и целей: карты и общий баланс, машина мечты, список покупок, календарь смен и задач. Сейчас это один HTML-файл (`legacy/index.html`, ~260 строк) с «сырым» видом. Нужно:

- тёмный дизайн в стиле «жидкое стекло» с сильными анимациями и продуманным UX;
- экран бюджета как главная Т-Банка (`docs/references/1-budget-tbank.webp`);
- починить кривое листание карт;
- добавить планировщик бюджета на месяц;
- пополнения «в одно касание» из уведомлений банка;
- экран мечты как карточка Porsche у Т-Банка (`docs/references/2-dream-tbank.webp`), машина нарисована в SVG;
- карточки покупок как «Draw a Chick» (`docs/references/3-buy-card.png`) — вырезанное фото товара выглядывает из карточки;
- календарь: дневная смена — жёлтое солнце, задачи с описанием под названием.

Референс стекла: `docs/references/4-liquid-glass.png`. Папка `docs/references/` в git не попадает (там личные скриншоты).

### Успех

- Все текущие данные пользователя (карты, машина, покупки, смены, задачи, план смен) после обновления на месте.
- Карты листаются плавно, без рывков и «недокрутки», свайп не мешает вертикальной прокрутке.
- В планировщике можно за пару минут расписать месяц по категориям и видеть остаток и дневной лимит.
- Пополнение из push-уведомления занимает одно касание задней панели iPhone + одно касание «Зачислить».
- 60 fps анимаций на iPhone в Telegram; при «Уменьшении движения» анимации упрощены.

## 2. Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Хостинг | GitHub Pages (как сейчас), тот же адрес | Сохраняется `localStorage` пользователя |
| Стек | React 19 + Vite + TypeScript + Motion (`motion/react`) | Пружины, жесты, переходы; поддерживаемость |
| Деплой | GitHub Actions собирает и публикует Pages при push; push делает Claude после одобрения | Пользователь попросил деплоить за него |
| Уведомления | iPhone, только push → «Быстрая команда» по касанию задней панели: снимок экрана → распознавание суммы → ссылка `startapp` | iOS не даёт читать чужие push; сервер не нужен |
| Синхронизация на двоих | Следующая часть (Firebase Firestore). Сейчас — только готовый к ней слой данных | Сначала результат по дизайну |
| Общие данные (на будущее) | Карты, пополнения, бюджет, мечта, покупки. Личные: смены, задачи, план смен, настройки | Ответ пользователя |
| Машина | Детальная SVG-иллюстрация Porsche Panamera, цвет кузова настраивается | Ответ пользователя |
| Траты планировщика | Не списываются с балансов карт | Иначе двойной учёт при ручной правке баланса |

## 3. Не входит в эту часть

- Синхронизация на двоих, приглашение по ссылке `join_…`.
- Автоматическое фото товара по ссылке на страницу магазина (нужен сервер).
- Починка Playwright MCP (отдельная задача окружения).
- Несколько «мечт» одновременно.

## 4. Архитектура

```
  lib/

    images.ts              IndexedDB для картинок (put/get/delete Blob)
    cutout.ts              удаление однотонного фона и средний цвет (чистая функция над ImageData)
    tilt.ts                наклон телефона → CSS-переменные для бликов стекла
  ui/                      Glass, Sheet, AnimatedNumber, Ring, Donut, ProgressLiquid,
                           Keypad, Toast, Icon, PressableButton, ScreenTransition
  screens/
    budget/                BudgetScreen, CardPocket, ActionRow, AccrualsSheet, TopUpSheet,
                           TransferSheet, BankForm, SearchSheet
    planner/               PlannerPage, CategorySheet, SpendForm, CategoryForm
    shortcut/              ShortcutGuidePage, IncomingTopUpSheet
    dream/                 DreamScreen, PanameraSvg, DreamForm
    buys/                  BuysScreen, BuyCard, BuyForm
    calendar/              CalendarScreen, DaySheet, TaskCard, ShiftForm, TaskForm
  styles/                  tokens.css, glass.css, base.css
```

Правила границ:
- `lib/*` не импортирует React (кроме хука в `store.ts`); всё чистое и покрыто тестами.
- Экраны читают состояние только через `useStore(selector)` и меняют только через экшены `store.ts`.
- `telegram.ts` — единственное место, где трогается `window.Telegram`.

## 5. Данные

### 5.1 Модель v4

```ts
type BankCode = 'alfa' | 'sber' | 'vtb' | 'tbank' | 'ozon';

interface Rec { id: string; updatedAt: number; deleted?: true } // готово к синхронизации

interface Bank extends Rec { code: BankCode; sum: number; order: number }
interface Income extends Rec {
  date: string;            // YYYY-MM-DD
  amount: number;          // ₽, > 0
  bankId: string;
  source: 'manual' | 'shortcut';
  note?: string;
}
interface Car { name: string; price: number; date: string; color: string; imgId?: string; updatedAt: number }
interface Buy extends Rec { title: string; url: string; price: number; imgId?: string; tint?: string }
interface Category { id: string; name: string; icon: string; color: string; limit: number }
interface BudgetMonth extends Rec { ym: string; income: number; cats: Category[] } // id === ym
interface Spend extends Rec { ym: string; catId: string; amount: number; date: string; note?: string }
interface Shift extends Rec { date: string; type: 'd' | 'n'; pay: number; h: number }
interface Task extends Rec { title: string; desc: string; due: string; done: boolean }

interface StateV4 {
  v: 4;
  shared: { banks: Bank[]; incomes: Income[]; car: Car; buys: Buy[]; budgets: BudgetMonth[]; spends: Spend[] };
  personal: {
    shifts: Shift[]; tasks: Task[]; plan: number;
    settings: { botLink: string; lastTopUpBankId?: string };
    processedLaunches: string[]; // последние 50 ключей запуска
  };
}
```

Удаление — пометка `deleted: true` (нужно будущей синхронизации); интерфейс такие записи не показывает.

### 5.2 Хранение и миграция

- Ключ `planner_v4` в `localStorage`. При его отсутствии читается `planner_v3` и проходит через `migrate.ts`: числовые `id` → строки, `code` у карт вычисляется как в старой функции `code()`, `updatedAt = Date.now()`, `order` по текущему порядку, новые коллекции пустые. `planner_v3` не изменяется и не удаляется.
- Битый JSON в `planner_v3` → старт с пустым состоянием и тост «Старые данные не прочитались», `planner_v3` не трогаем.
- Сохранение с задержкой 150 мс после последнего изменения и при `visibilitychange: hidden`.
- Картинки (фото товаров, своё фото машины) — Blob в IndexedDB (`planner-images`), в состоянии только `imgId`.
- Режим `?demo=1` — демо-данные под ключом `planner_demo`, реальные данные не затрагиваются (для проверки и скриншотов).

## 6. Визуальная система

### 6.1 Токены
- Фон `#000`, текст `#fff`, вторичный `rgba(235,235,245,.6)`, третичный `.35`.
- Акценты: жёлтый `#FFDD2D` (основной, дневные смены), зелёный `#30D158` (доход), красный `#FF453A` (превышение), синий `#8AB4FF` (ночные смены), фиолетовый `#6E4BFF` (кнопка планировщика).
- Цвета банков — градиенты из текущей версии, доработанные под стекло.
- Радиусы: 36 (большие карточки), 28 (карточки), 20 (строки), 999 (пилюли).
- Шрифт: системный (`-apple-system, SF Pro`), цифры `tabular-nums`.

### 6.2 Стекло
- Слой: `backdrop-filter: blur(24px) saturate(180%)`, фон `rgba(255,255,255,.06)`.
- Кромка: градиентная рамка 1px (светлая сверху-слева → прозрачная), внутренние блики `inset 0 1px 0 rgba(255,255,255,.22)`.
- Блик-отсвет: радиальный градиент, позиция зависит от `--tilt-x/--tilt-y` (Telegram `DeviceOrientation`, частота 20 Гц, только когда приложение видно; без API — статичный).
- В Chromium (Android, Desktop) — дополнительное преломление через SVG `feDisplacementMap` для нижней панели и кнопок; в WebKit (iPhone) — без него.
- Фон приложения: 2–3 размытых тёмных цветовых пятна, медленно плавающих; на экране бюджета пятна берут цвет активной карты.
- Лимит: одновременно в кадре не больше ~8 слоёв с `backdrop-filter`.

### 6.3 Движение
- Пружины: `snappy` (stiffness 520, damping 38), `soft` (260, 30), `bouncy` (380, 22).
- Переход вкладок: сдвиг ±24px по направлению + прозрачность + размытие 6px → 0.
- Появление содержимого: каскад 40 мс.
- Суммы: перекатывающиеся цифры (каждый разряд — вертикальная лента).
- Шторки: тянутся пальцем, закрываются свайпом вниз (порог 25% высоты или скорость).
- Нажатие: `scale(.96)` + вибрация `light`; успех — `notificationOccurred('success')`.
- `prefers-reduced-motion` → только прозрачность, без сдвигов и пружин.

### 6.4 Навигация и Telegram
- Плавающая стеклянная панель снизу: 4 вкладки с подписями (Бюджет, Мечта, Покупки, Календарь) + белая круглая «+». Активная вкладка — стеклянная «капля», перетекающая пружиной (`layoutId`).
- Telegram: `ready`, `expand`, на мобильных `requestFullscreen` с учётом `safeAreaInset`/`contentSafeAreaInset`, `disableVerticalSwipes`, цвета шапки/фона/нижней панели `#000`, системная `BackButton` для страниц (планировщик, инструкция).
- Без Telegram (браузер): те же экраны, своя кнопка «Назад», вибрация — no-op.

## 7. Экраны

### 7.1 Бюджет
Сверху вниз:
1. Плашка «Операции» со скруглённым низом. Нажатие раскрывает: «Сумма всех покупок», «На счетах после покупок».
2. Строка: аватар (`photo_url` из Telegram или инициал на градиенте), стеклянное поле «Поиск», фиолетовая круглая кнопка → планировщик.
3. Точки по числу карт; пилюля «<Банк> · <баланс карты>»; общий баланс крупно (перекатывающиеся цифры).
4. **Карман с картами** (`CardPocket`):
   - карты абсолютно позиционированы, положение — непрерывная величина `x` (индекс с дробью), управляется жестом;
   - активная карта приподнята из кармана на 24px, соседние видны по краям: `scale .86`, ниже на 18px, прозрачность .6;
   - жест на pointer-событиях, `touch-action: pan-y`; при отпускании — цель по позиции + скорости (порог 0.3 карты или 400 px/с), пружина `snappy`; на краях — сопротивление 0.35;
   - смена карты → вибрация `selection`, обновление пилюли и точек;
   - передний слой кармана — SVG-форма с плавным вырезом по центру и светлой кромкой;
   - нажатие на активную карту → редактирование (банк, баланс, удаление); пустое состояние — «Добавьте карту».
5. Ряд круглых стеклянных кнопок (листается вбок): Пополнить, Перевести, План, Автопополнение, Новая карта.
6. Карточка **«Начисления»**: «Начислено в <месяц> N ₽» (сумма оплат смен месяца), справа стопка до 3 мини-иконок последних записей среди смен и пополнений (солнце / луна / цвет банка). Нажатие → шторка с вкладками «Смены» / «Пополнения», записи сгруппированы по датам.
7. Карточка **«Бюджет на <месяц>»**: «Осталось X из Y ₽», справа мини-кольцо. Нажатие → планировщик.

Экран прокручивается вертикально.

### 7.2 Поиск
Шторка с полем ввода; ищет без учёта регистра по покупкам (название), задачам (название, описание), пополнениям (сумма, заметка), категориям и тратам (название, заметка). Результаты по группам; нажатие открывает нужную вкладку/запись.

### 7.3 Планировщик (страница поверх, BackButton)
- Переключатель месяца ‹ Октябрь 2026 ›.
- Большой «пончик»: сегменты — лимиты категорий их цветами, поверх — заполнение потраченным. Центр: «Осталось X ₽» и «из Y ₽».
- Под ним: «Можно тратить ~D ₽ в день · до конца месяца N дн.» — только для текущего месяца; `D = max(0, Σлимитов − Σпотрачено) / дней_до_конца_включая_сегодня`.
- «Доход на месяц» — редактируемое значение с подсказками: «по сменам: …», «на картах: …». Полоса «распределено / свободно»; если распределено больше дохода — предупреждение.
- Список категорий: иконка, название, полоса «потрачено / лимит», суммы; при превышении полоса и сумма красные.
- Нажатие на категорию → шторка: изменить лимит/название/иконку/цвет, список трат, «Добавить трату», удалить категорию.
- «+ Трата» на странице: сумма (клавиатура), категория (чипы), заметка, дата (по умолчанию сегодня).
- Пустой месяц: «Скопировать план <прошлого месяца>» (если есть) и «Начать с шаблона» (Жильё, Еда, Транспорт, Связь, Развлечения, Здоровье, Накопления на мечту).

### 7.4 Пополнения
- **Пополнить**: шторка с крупной клавиатурой и выбором карты; по «Зачислить» баланс карты растёт (анимация), создаётся `Income { source: 'manual' }`.
- **Перевести**: с карты → на карту, сумма; меняет два баланса, в начисления не пишется; нельзя перевести больше баланса.
- **Параметр запуска** `inc_<сумма>` или `inc_<сумма>_<bank>`: сумма — целые рубли, 1…10 000 000; `bank` ∈ BankCode. Открывает шторку «+5 000 ₽ → <карта>» (карта: по банку → последняя использованная → первая), кнопки «Зачислить» / «Отмена». Ключ повтора `auth_date:start_param` хранится в `processedLaunches`; при повторе шторка не показывается. В браузере параметр читается из `?tgWebAppStartParam=`.
- **Страница «Автопополнение»**: пошаговая инструкция для «Быстрых команд» (Снимок экрана → Извлечь текст из изображения → Сопоставить текст с готовым выражением → Получить группу → Заменить нецифровые символы → Открыть URL) и настройки «Касание задней панели»; кнопки копирования выражения и ссылки; поле «Ссылка на бота» (`settings.botLink`, например `https://t.me/my_bot`), из которого собирается URL `…?startapp=inc_`.
- Выражение для суммы (в `shortcut.ts`, покрыто тестами на текстах Т-Банка, Сбера, Альфы, ВТБ, Озона): ищет сумму рядом со словами «пополнение / зачисление / поступление / перевод от / входящий перевод» или со знаком «+», с ₽/руб/р/RUB/RUR.

### 7.5 Мечта
- Карточка как у Т-Банка: тёмный вертикальный градиент, радиус 36, название крупно по центру, стеклянный чип «✦ Авто мечты», под ним `PanameraSvg` (цвет кузова из `car.color`) с отражением и тенью. Если задано своё фото (`car.imgId`) — показывается оно (с вырезанным фоном).
- Вход на вкладку: машина «въезжает» справа с лёгким покачиванием, по кузову проходит блик.
- Под карточкой:
  - «Накоплено X из Y ₽» — общая сумма на картах, «жидкая» полоса и процент;
  - три плитки «в день / в неделю / в месяц» до срока (если есть срок и цель не достигнута);
  - прогноз: при доходе со смен за последние 30 дней — месяц и год достижения (если доход > 0);
  - сколько дней до срока;
  - вехи 25/50/75/100 %.
- Нет цены → призыв «Укажите цену и срок» с кнопкой. Нажатие на карточку → форма мечты (название, цена, дата, цвет, своё фото).

### 7.6 Покупки
- Сверху: «Сумма покупок» крупно + пилюля «Останется на счетах: …».
- Сетка 2 колонки, карточки `BuyCard`:
  - стеклянная, подкрашена `tint` (средний цвет фото) или цветом из палитры по названию;
  - слева сверху цена (мелко), ниже название (крупно, до 2 строк);
  - справа снизу фото без фона, выходит за верхний край карточки примерно на половину своей высоты; без фото — крупная объёмная иконка по названию (набор из текущей версии);
  - нажатие → ссылка; долгое нажатие → меню «Изменить / Удалить».
- Форма: название, ссылка, цена, фото — «Из галереи» или «По ссылке на картинку». После выбора — превью с переключателем «Убрать фон».
- `cutout.ts`: уменьшение до 768px, медианный цвет рамки; если рамка однотонная (разброс < порога) — заливка от краёв с допуском, сглаживание края 1–2px, обрезка прозрачных полей, средний цвет → `tint`. Если фон неоднородный — фон не убирается, картинка показывается с мягкой маской. Картинка по ссылке без CORS → без вырезания, с маской.

### 7.7 Календарь
- Сверху кольца «Выполнено» и «Смены» (нажатие на «Смены» → план смен в месяц).
- Сетка месяца: дневная смена — **жёлтое солнце с лучами** + сумма жёлтым + лёгкая жёлтая подсветка ячейки; ночная — синяя луна; сегодня — жёлтая обводка; выбранный день — светлое стекло; точка-маркер, если есть задачи.
- Шторка дня: сводка смен («Дневная смена · 12 ч · 4 500 ₽»), карточки задач: анимированная галочка, жирное название, **описание под названием** (до 3 строк, нажатие раскрывает), удаление; кнопка «Добавить» (задача / смена).

## 8. Ошибки и граничные случаи

- `localStorage` переполнен / недоступен → тост «Не удалось сохранить», состояние остаётся в памяти.
- IndexedDB недоступен → выбор фото скрыт, подсказка.
- Неверный `start_param` → игнорируется.
- Суммы: ввод только цифр, максимум 1 000 000 000 ₽ (в параметре запуска — 10 000 000 ₽); отрицательные балансы не допускаются при переводе.
- Нет карт → пополнение предлагает сначала добавить карту.
- Месяц без бюджета → пустое состояние планировщика.

## 9. Тестирование
